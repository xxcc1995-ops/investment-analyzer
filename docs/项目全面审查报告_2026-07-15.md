> 方法：CLAUDE.md 通读 → 模块结构梳理 → 核心地基代码精读 → 全量工程坏味道扫描 → 功能逻辑抽查

## 一、整体评价

项目体量大、功能全，**地基工程扎实**，远超一般个人项目水准：

- ✅ 多源行情聚合层 `services/quote_sources/` + `multi_source_quote.py`：优先级容错、60s 冷却、批量降级，设计成熟。
- ✅ 集中式缓存 `core/cache.py`：LRU + 分层 TTL + 交易时间感知（盘中 30s / 盘后 300s）+ 线程安全 + 文件持久化。
- ✅ 安全中间件齐全：CORS 白名单、API_KEY 认证、请求超时、统一异常注册、输入校验工具、敏感前缀保护。
- ✅ 可转债模块严格对齐 CLAUDE.md「宁可空着」：`_CB_REQUIRED_FIELDS` 字段门控，AKShare 缺字段时策略返回空+提示，不展示伪候选。
- ✅ `data_service` 记录 `fetch_time`、按 `REPORT_DATE` 排序取最新报告期，符合时效性要求。

**结论：架构方向正确、关键风控到位。问题集中在"工程卫生"与"一致性"层面，非结构性缺陷。**

## 二、功能逻辑审查

### 2.1 行情与搜索（stocks / data_service / multi_source_quote）
- 逻辑正确。多源容错链 A股(通达信→新浪→东方财富)、港股(通达信→腾讯→东方财富)实现完整，失败源冷却后二次重试。
- **缺口（低优先级）**：`QuoteData` 已带 `trade_date`/`timestamp` 字段，但 `data_service.get_stock_basic` 取到行情后**未校验行情日期是否为当日/上一交易日**。CLAUDE.md 规则1要求"实时行情必须是当天的或上一交易日收盘"。当前靠 30s 缓存 + 源自带时效隐式保证，无显式拦截。建议：盘后若 `trade_date` 早于上一交易日则标记 stale。
- **工程问题**：约 20 处服务（cigar_butt/fund_utils/right_side/relative_valuation/grid/t_trading/national_team/daily_info/reit 等）**绕过** `quote_sources` 聚合层，各自直连 `qt.gtimg.cn`/新浪并重复 GBK 解析。既违反 DRY，又使这些路径**失去多源容错与冷却保护**。见 §三-3。

### 2.2 估值体系（valuation / sector_valuation / relative_valuation / index_valuation）
- `sector_valuation`：api/services 双文件职责分离（路由 vs 计算），无重复，逻辑清晰。
- `relative_valuation`：组内分位数 + 中位数偏离 + 综合评分评级，缺字段留 None 不编造，符合可靠性原则。
- `index_valuation`：SPX 全 multpl.com、NDX 仅 PE、SPXDIV 全 null——不可靠数据已剔除，处理审慎。
- **建议**：三类估值（绝对/行业/相对）评级口径（低估/合理/偏高/高估）应统一为常量枚举，避免各服务硬编码字符串散落。

### 2.3 可转债（cb / cb_backtest）
- 三级容错（集思录API→集思录网页版Scrapling→AKShare）已落地，字段门控正确。**这是全项目风控最严的模块，无需改动。**
- **待复核（中优先级）**：CLAUDE.md 回测表显示「安道全面值 / 双低 / 摊大饼」三个**不同策略**的年化(15.54%)/回撤(-13.43%)/夏普(0.93)**完全相同**。统计上极不寻常，疑为共享选股逻辑或结果复制。建议复核 `cb_backtest_service` 三策略是否真正独立计算。

### 2.4 套利与交易（fund_arb / grid / t_trading / right_side / futu_options）
- `fund_arb` 子模块拆分细（fund_arb_engine/fund_config/fund_est/fund_est_engine/fund_t_strategy/fund_utils），均被 import，非死代码。
- **死代码**：`api/fund_est_detail.py` 全仓无引用，文件头自注"已迁移到 fund_arb.py"，应删除。
- `grid`/`t_trading`/`right_side` 内 `except Exception: pass` 较多（吞异常不记录），交易类逻辑静默失败风险高，建议至少 logger.warning。

### 2.5 宏观与资讯（macro / daily_info / overseas_news / rss）
- 海外资讯 T1/T2 分级、影响力评估、多源交叉验证，设计完整。
- `macro.py` 多处 `except Exception: pass`（210/223/261/301）+ 1 处裸 `except:`（1062），宏观数据缺失时静默返回空，前端难区分"无数据"与"接口异常"。

### 2.6 预测市场与币圈（polymarket / crypto_master / airdrop_scanner / crypto_crawler）
- `prediction_market/` 下用 `print()` 而非 logger（opinion.py / polymarket.py 多处），且含裸 except。
- **安全**：`/api/polymarket`（含 cross_arbitrage、allocation_calculator 交易计算）与 `/api/crypto-crawler`（含主动 /crawl 触发）**未纳入 SENSITIVE_PREFIXES**，与其交易/触发性质不符。

### 2.7 回测（backtest / quant 引擎）
- `/api/backtest` 路由保留（策略验证页与做T系统共用），`quant` 引擎包因 backtest_service 依赖保留——与记忆中"删除回测页但保留后端路由"一致，无问题。
- `real_backtest.py` 仅被 backend 根脚本引用，app 内半孤儿，可保留但建议注明用途。

## 三、软件工程层面优化点

### 3.1 死代码 / 孤儿（P2，低风险，建议清理）
| 文件 | 状态 | 建议 |
|------|------|------|
| `api/fund_est_detail.py` | 全仓无引用，自注已迁移 | 删除 |
| `services/tushare_service.py` | app 内无人 import | 确认是否废弃，否则删除 |
| `services/neodata.py` | app 内无人 import | 同上 |

### 3.2 异常处理（P1，影响可观测性与真金白银安全）
- 裸 `except:` 15 处（macro/fund_service/futu_option/quant/*/prediction_market/*/tdx_source）。
- `except Exception: pass` 30+ 处，集中在 valuation/macro/grid/t_trading/right_side/akshare。
- **建议**：统一改为 `except <具体异常> as e: logger.warning(...)`；交易/套利类逻辑禁止静默吞异常。

### 3.3 重复行情抓取逻辑（P1，DRY + 容错缺失）
- 20 处直连腾讯/新浪 + `r.encoding='gbk'` 重复实现，绕过 `quote_sources` 聚合层。
- **建议**：所有行情获取统一走 `multi_source_service.get_quote/get_batch_quotes`；批量取名称等轻量场景可保留腾讯直连但抽到 `core/utils` 单一实现。

### 3.4 输入校验（P1，安全）
- 仅 `api/stocks.py` 用了 `validate_stock_code/validate_keyword`。
- valuation/fund_arb/right_side/cb/futures/macro/jc/daily_info/national_team 等大量路由裸接 `Query()` 参数无格式校验。
- **建议**：所有接收 stock_code/fund_code/codes 的路由统一套 `validate_*`，防路径遍历/超长/注入（CLAUDE.md 已有安全加固，但覆盖不全）。

### 3.5 同步阻塞（P2，性能）
- `core/rate_limiter.py:12` 中间件内 `requests.get` 同步阻塞。
- `async def` 路由（quantdinger/polymarket 部分）间接调用同步 `requests` 链路，阻塞事件循环。
- **建议**：中间件改 `httpx.AsyncClient`；或同步路由统一用 `def`（FastAPI 会丢线程池），避免 async 路由内同步 IO。

### 3.6 日志规范（P2）
- 多处 `print()`（backtest_service 测试残留、real_backtest、prediction_market/*）。
- main.py 未见 `logging.basicConfig`，默认 WARNING 级，DEBUG/INFO 日志可能不输出。
- **建议**：统一 logger，配置 root logging（级别可 env 控制），清除 print。

### 3.7 文档与配置漂移（P1，运维）
- **CLAUDE.md 仍写"后端 8002 / 前端 5173"**，但实际已迁至 **8022 / 5180**（避僵尸端口）。`start.bat`/`start.ps1`/`vite.config.ts` 均用新端口。文档与代码不一致会误导未来维护。
- **建议**：更新 CLAUDE.md 启动命令与访问地址为 8022/5180，并注明 8002 为僵尸端口、勿用。

### 3.8 缓存装饰器（P2，小瑕疵）
- `@cached(ttl_seconds=TTL_REALTIME)` 用装饰时固定 TTL，不动态调 `get_realtime_ttl()`，故"盘后延长到 300s"对被装饰实时函数不生效（固定 30s，更保守，影响小）。
- **建议**：实时函数若需盘后延长，显式 `ttl_seconds=get_realtime_ttl()` 或在装饰器内动态求值。
