### 完成 - 第三轮：新代码已运行但仍 504（yfinance 429 限流 + 超时阻塞 bug + 串行拖垮）
- **现象**：日志 21:53 显示新代码已在跑（出现"返回旧缓存兜底"、富途风暴消失），但接口仍 504。日志全是 `获取ETF 2800.HK/QQQ/EWJ...估值失败: Too Many Requests. Rate limited.`。
- **根因三连**：
  1. **yfinance 全线 429 限流**：用户反复刷新触发 yfinance 限流，所有 ETF 估值（恒生/全球/纳指fallback）全 429；yfinance 库内部退避重试，每次调用耗时十余秒。
  2. **超时阻塞 bug**：`get_all_indices_data` 用 `with ThreadPoolExecutor(max_workers=1)`，其 `__exit__` 会 `shutdown(wait=True)` 阻塞等后台线程；`fut.result(timeout=30)` 超时抛异常后，`with` 退出仍卡等 yfinance 退避线程（数分钟）→ 被 60s `RequestTimeoutMiddleware` 返回 504。30s 超时形同虚设。
  3. **19 指数串行**：yfinance 429 退避 × 多指数串行，累积远超 30s；超时后返回空壳（旧缓存空）→ 用户看不到任何数据。
- **修复**（index_valuation_service.py）：
  1. `get_all_indices_data`：去掉 `with`，手动管理 executor；超时后 `ex.shutdown(wait=False, cancel_futures=True)` 不阻塞，立即返回旧缓存/兜底；超时 30→50s（中间件 60s 留余量）。
  2. `_get_etf_pe_pb`：加 yfinance 429 短路（全局 `_yf_rate_limited_ts`，5分钟内所有 yfinance 调用直接返回空，不再逐个等退避）。

### 完成 - 第四轮：start.ps1 Kill-Port PID 0 崩溃 bug（重启失败真因）

- **修复**（start.ps1 Kill-Port）：① 跳过 PID 0 和自身 `$PID`；② 函数内临时 `$ErrorActionPreference = "Continue"` 隔离 taskkill 错误，结束后恢复。CLAUDE.md 启动描述已同步为"强制重启"。
