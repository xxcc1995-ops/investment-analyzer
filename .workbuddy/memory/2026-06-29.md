## 安全审计

对项目进行了全面安全审计，发现以下风险：
- **高风险**：CORS `allow_origins=["*"]` 宽松配置（main.py:105）；所有 API 端点无认证机制
- **中风险**：futu_options.py 中 `_run_futu_script` 写临时脚本并 subprocess 执行（经核实为内部生成脚本，非用户直接输入，但仍是代码执行风险点）；临时文件使用固定路径名（竞争条件）；API 缺少速率限制；输入参数缺少格式校验
- **低风险**：异常日志可能含敏感信息；前端 localStorage 使用
- **良好实践**：SSRF 防护已实现（scraper.py）；SQL 使用参数化查询；密钥通过环境变量读取（FRED_API_KEY/TUSHARE_TOKEN/QUANTDINGER_PASSWORD 等）；.gitignore 正确排除了 .env 和登录凭证文件；无 eval/exec/os.system 调用；前端无 dangerouslySetInnerHTML

## 安全修复（按优先级）

### 1. CORS 白名单修复（高风险→已修复）
- `backend/app/main.py`：`allow_origins=["*"]` → 白名单模式
- 默认允许 `localhost:5173/3000`，支持 `ALLOWED_ORIGINS` 环境变量覆盖
- `allow_credentials=True`，方法限制为 `GET/POST/PUT/DELETE/OPTIONS`

### 2. 清理脚本执行隐患（中风险→已修复）
- `backend/app/api/futu_options.py`：删除未被调用的 `_run_futu_script` 函数
- 移除 `subprocess`、`json`、`sys` 导入，消除任意代码执行风险点

### 3. API Key 认证中间件（高风险→已修复）
- 新建 `backend/app/core/security_middleware.py`：`ApiKeyMiddleware`
- 保护敏感端点：tractor/portfolio/futu-options/grid/cb/fund-arb
- 未设置 `API_KEY` 环境变量时自动跳过（本地开发零配置）
- 前端 `frontend/src/services/api/client.ts`：请求拦截器自动携带 `X-API-Key`
- 新建 `frontend/src/vite-env.d.ts`：Vite 环境变量类型声明
- 新建 `frontend/.env.example`：配置示例

### 4. 输入校验加固（中风险→已修复）
- 新建 `backend/app/core/validators.py`：`validate_stock_code`/`validate_keyword`
- `backend/app/api/stocks.py`：搜索和行情接口添加输入验证
- 阻止路径遍历（`../`）、超长输入、特殊字符注入

### 5. 日志敏感信息过滤（低风险→已修复）
